### 2. Alfred↔HAL Handoff Protocol ✅

**Problem:** HAL sometimes receives ambiguous tasks → rework, feature creep. No formal contract between Alfred + HAL.

**Solution:** Structured handoff JSON schema enforced before dispatch:
- Required: objective, constraints, deliverables (code/tests/docs), validation_command, success_criteria, owner, deadline
- Schema validation (JSON schema + jq)
- Dispatcher gating (validates before queue assignment)
- Clear acceptance flow (HAL posts "Accepted" + restatement to kanban)
- Explicit rejection + rework cycle

**Files:**
- `schemas/handoff.json` — JSON schema (13 properties, validation rules)
- `scripts/validate-handoff.sh` — Validation CLI (9 checks, clear error messages)
- `goals/handoffs/TEMPLATE.json` — Template for new handoffs
- `goals/handoffs/card_001.json` — Example (preflight handshake task)
- `HANDOFF-PROTOCOL.md` — Full documentation (11KB, includes examples)

**Testing:**
- Validated card_001 → ✅ All checks pass
- Schema includes deadline future-check, task_id format, min field lengths

## Known Issues & Workarounds

**Issue 1:** OPEN-LOOPS refresh script uses `date -v+1d` (macOS-specific)
- ✅ **Workaround:** Already using BSD date syntax (compatible with macOS)
- **Note:** If running on Linux, use `date -d "tomorrow"` instead

**Issue 2:** Decision guard only checks exact title match
- ✅ **Workaround:** Titles should be unique + consistent (e.g., "Q2 App Priority", not "app priority Q2")
- **Note:** Fuzzy matching can be added later if needed

**Issue 3:** Handoff schema doesn't support conditional fields
- ✅ **Workaround:** Optional fields go in `context` object
- **Note:** Covers 95% of use cases; simple enough to expand if needed
