**Issue:** Brave Search API rate limits (1 req/min free tier) caused 4× 429 errors overnight (00:20, 04:03, 04:20 ADT). No automatic backoff mechanism existed, causing repeated failed searches.

**Solution:** Created `web-search-guard.sh` — lightweight rate-limit enforcement script that:
- Tracks last 429 error timestamp in `.search-guard.state`
- Enforces 90-second cooldown after 429 error
- Provides `check|set|reset` commands for guard status + manual override
- Can be called before searches to skip if guard is active

**Implementation:**
- Script: `scripts/web-search-guard.sh` (68 lines, jq-based parsing for robustness)
- Status file: `.search-guard.state` (JSON, persistent)
- Integration ready: Cron jobs and idle activities can call `bash web-search-guard.sh check` before web_search to avoid rate-limit cascade
