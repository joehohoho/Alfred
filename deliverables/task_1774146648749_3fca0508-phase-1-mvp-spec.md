## Overview

Phase 1.0 delivers the **core expense management workflow** without integrations. Focus: multi-tenant architecture, approval routing, categorization, and reporting.

**User Journey:**
1. Org admin invites employees
2. Employee submits expense (description, amount, category, date, receipt upload)
3. Manager approves or rejects
4. Finance team reconciles and prepares settlement
5. Finance team views aggregate reports

---

## User Roles & Permissions

### Role: Admin
- Create org, invite/remove users, assign roles
- Configure approval routing (auto-approver, multi-tier)
- View all expenses, reports
- Settings (org name, logo, payment method)

### Role: Manager
- Approve/reject direct reports' expenses
- View team expenses
- Submit own expenses
- View team reports

### Role: Employee
- Submit expenses
- View own expenses (status, feedback)
- No approval authority

### Role: Finance (New)
- View all expenses (all departments)
- Bulk review & approval
- Settlement operations (Interac, manual)
- Generate reports (T5018, category summaries)

---

### 3. Approval Workflow
**In Scope:**
- [ ] Expense status flow: Draft → Submitted → Approved/Rejected → Settled
- [ ] Manager approval UI (list view, detail view, bulk actions)
- [ ] Rejection with comment/reason
- [ ] Email notifications (submit, approved, rejected)
- [ ] Default approver assignment (based on employee's manager field)

**Out of Scope:**
- Multi-tier approval (e.g., Manager → Finance → CEO)
- Policy-based approval rules (Phase 2)
- Escalation workflows

**Approval Routing Config:**
```
Employee submits
  ↓
Manager notified (email)
  ↓
Manager approves or rejects
  ↓
If approved → Submitted
If rejected → Draft (employee can fix)
  ↓
Finance team views approved expenses
  ↓
Finance can mark as Settled (Interac, check, etc.)
```

## Database Schema (MVP)

```sql
-- Organizations
CREATE TABLE organizations (
  id UUID PRIMARY KEY,
  name VARCHAR(255),
  industry VARCHAR(100),
  currency VARCHAR(3) DEFAULT 'CAD',
  logo_url TEXT,
  created_at TIMESTAMP,
  updated_at TIMESTAMP
);

-- Users (belongs to org)
CREATE TABLE users (
  id UUID PRIMARY KEY,
  org_id UUID REFERENCES organizations,
  email VARCHAR(255),
  name VARCHAR(255),
  role ENUM('admin', 'manager', 'employee', 'finance'),
  manager_id UUID REFERENCES users, -- NULL for admin/finance
  created_at TIMESTAMP,
  updated_at TIMESTAMP
);

-- Expenses
CREATE TABLE expenses (
  id UUID PRIMARY KEY,
  org_id UUID REFERENCES organizations,
  submitter_id UUID REFERENCES users,
  amount DECIMAL(10, 2),
  currency VARCHAR(3),
  description TEXT,
  category VARCHAR(100),
  date DATE,
  status ENUM('draft', 'submitted', 'approved', 'rejected', 'settled'),
  approver_id UUID REFERENCES users, -- Manager who approved
  rejection_reason TEXT,
  receipt_urls JSONB, -- Array of S3/local URLs
  created_at TIMESTAMP,
  updated_at TIMESTAMP
);

-- Approval History (audit trail)
CREATE TABLE approval_history (
  id UUID PRIMARY KEY,
  expense_id UUID REFERENCES expenses,
  user_id UUID REFERENCES users,
  action ENUM('submitted', 'approved', 'rejected'),
  reason TEXT,
  created_at TIMESTAMP
);

-- Tags
CREATE TABLE tags (
  id UUID PRIMARY KEY,
  org_id UUID REFERENCES organizations,
  name VARCHAR(100),
  created_at TIMESTAMP
);

-- Expense-Tag mapping
CREATE TABLE expense_tags (
  expense_id UUID REFERENCES expenses,
  tag_id UUID REFERENCES tags,
  PRIMARY KEY (expense_id, tag_id)
);
```

## API Endpoints (MVP)

### Organizations
```
POST   /api/orgs                          # Create org (admin only)
GET    /api/orgs/{org_id}                # Get org details
PATCH  /api/orgs/{org_id}                # Update org settings
```

### Users
```
POST   /api/orgs/{org_id}/users          # Invite users
GET    /api/orgs/{org_id}/users          # List users
PATCH  /api/orgs/{org_id}/users/{user_id} # Update role/manager
DELETE /api/orgs/{org_id}/users/{user_id} # Remove user
```

### Expenses
```
POST   /api/orgs/{org_id}/expenses       # Create/submit expense
GET    /api/orgs/{org_id}/expenses       # List expenses (filtered by role)
GET    /api/orgs/{org_id}/expenses/{id}  # Get expense details
PATCH  /api/orgs/{org_id}/expenses/{id}  # Edit expense (draft only)
POST   /api/orgs/{org_id}/expenses/{id}/submit # Submit for approval
POST   /api/orgs/{org_id}/expenses/{id}/approve # Manager approval
POST   /api/orgs/{org_id}/expenses/{id}/reject  # Manager rejection
```

### Reports
```
GET    /api/orgs/{org_id}/reports/summary # Dashboard summary
GET    /api/orgs/{org_id}/reports/list    # Expense list (paginated)
GET    /api/orgs/{org_id}/reports/export  # CSV export
```

### Settings
```
GET    /api/orgs/{org_id}/settings/approval-routing
PATCH  /api/orgs/{org_id}/settings/approval-routing
GET    /api/orgs/{org_id}/categories
POST   /api/orgs/{org_id}/categories      # Create custom category
```

## Tech Stack (Phase 1.0)

### Frontend
- **Framework:** React (leverage Even Us Up existing stack)
- **State Management:** Redux or Zustand
- **UI Library:** Tailwind CSS + shadcn/ui (or Ant Design)
- **Forms:** React Hook Form + Zod validation
- **File Upload:** React Dropzone + AWS S3 pre-signed URLs

### Backend
- **Runtime:** Node.js 18+
- **Framework:** Express.js or FastAPI (if migrating)
- **Database:** PostgreSQL 14+
- **ORM:** Sequelize or TypeORM
- **Authentication:** JWT (bearer tokens)
- **Authorization:** Role-based access control (RBAC) middleware
- **File Storage:** AWS S3 or Cloudinary
- **Email:** SendGrid or Mailgun
- **Environment:** Docker containerization

### Deployment
- **Hosting:** AWS ECS + RDS (or Vercel + Supabase if lightweight)
- **CI/CD:** GitHub Actions (lint, test, deploy)
- **Monitoring:** Sentry + DataDog logs

## Risks & Mitigations

| Risk | Mitigation |
|------|-----------|
| Database design complexity (multi-tenant isolation) | Use proven patterns (schema-per-org or row-level security); spike early |
| Approval routing edge cases | Build state machine early, test with pilot customers |
| Email delivery issues | Monitor SendGrid deliverability, test with dev domain |
| File upload failures | Implement retry logic + user feedback UI |
| Security (SQL injection, auth bypass) | Use ORM, parameterized queries; external security audit |
