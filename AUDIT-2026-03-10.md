## Failure Mode Analysis

### What happens if context exceeds 60%?
- ✅ Alfred executor skips execution
- ✅ Logs warning + reason
- ✅ Continues next cycle
- ✅ No cascade failure

### What happens if Alfred queue grows unbounded?
- ✅ Deduplication prevents re-queuing
- ✅ Queue is write-once
- ✅ Processor can clear it
- ✅ Daily monitor recommended

### What happens if Kanban API goes down?
- ✅ All calls have timeouts (5-10 sec)
- ✅ Executor skips if API unreachable
- ✅ Continues next cycle
- ✅ No request accumulation

### What happens if HAL and Alfred both try same card?
- ✅ Separate execution paths (in_progress vs todo)
- ✅ No shared resource contention
- ✅ Completion handler moves done cards
- ✅ Risk: NONE

### What happens if in_progress cards stack up?
- ✅ Completion handler moves done → Done/Review (every 30 min)
- ✅ Stale scan moves >12h idle → todo (every 4h)
- ✅ Alfred executor deduplicates queuing
- ✅ Risk: NONE (board can't lock up)
